# LMCAD — a CAD engine built to be driven by AI

[![engine](https://github.com/Himanshu8881212/CadEngine/actions/workflows/engine.yml/badge.svg)](https://github.com/Himanshu8881212/CadEngine/actions/workflows/engine.yml)
[![analysis-gate](https://github.com/Himanshu8881212/CadEngine/actions/workflows/analysis-gate.yml/badge.svg)](https://github.com/Himanshu8881212/CadEngine/actions/workflows/analysis-gate.yml)
[![license: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

A Rust CAD kernel with an exact B-rep side and an implicit/SDF side, a physics and
analysis layer on top, and one JSON op surface (161 ops) over all of it — because it is
meant to be operated by a language model rather than a mouse.

> **Status: alpha / experimental.** Only artifacts regenerated by the current export path
> and accepted by [`release.yml`](.github/workflows/release.yml) are release candidates.
> Committed historical STLs are not manufacturing certification.

## The rule

**Receipts, not claims.** Every measure names its `provenance`. Every export names its
`route` (`exact` or `voxel_healed`), whether it came out `watertight`, and — if it fell
back — a `demotion` block naming the first failing check with witness points on the
offending edges. When the kernel cannot do something exactly it **refuses** rather than
quietly degrading, and a model driving it may not claim anything the report does not say.

## Quickstart

```sh
cargo build -p kernel-api --release
./target/release/kernel-api run showcase/squatchee_spin/programs/prop_program.json --out-dir out/
```

That builds a real, printable part and prints its report: topology, analytic mass
properties, support-free check, and an export that names its route. Exit code is 0 only
if every gate in the program passed.

A program is plain JSON — ops in, receipts out:

```json
{"ops": [
  {"id": "plate", "op": "box", "min": [0, 0, 0], "max": [60, 40, 8]},
  {"id": "check", "op": "validate", "in": "plate"},
  {"id": "vol",   "op": "exact_volume", "in": "plate"},
  {"id": "out",   "op": "export_stl", "in": "plate", "file": "plate.stl"}
]}
```

**As MCP tools** (Claude Code and any MCP client): build `cargo build -p studio-mcp
--release` and use [`.mcp.json`](.mcp.json), which is project-scoped. The model gets ten
tools: `run_program`, `describe_api`, `run_assembly`, `ace_fea`, `ace_optimize`,
`ace_modal`, `ace_buckling`, `graded_infill`, `production_check`, `render_views`.

The op reference is [`API.md`](API.md); the operator manual for a model driving the
engine is [`DESIGN_GUIDE.md`](DESIGN_GUIDE.md).

## The worked example

[**SQUATCHEE-SPIN**](https://www.printables.com/model/1777704-squatchee-spin) — a clip-on
propeller for the button on a baseball cap. Three printed parts, 9.9 g, no hardware, no
supports, designed and gated end to end by a model driving this engine. It went up on
Printables against 203 human-made entries, took 3rd by likes, and 1.2 K people downloaded
and printed it. Then the field reported the mast snapping; v2 replaced the snap-post with
a bayonet lock, and the receipts proved the fix before the filament was spent.

Everything it shipped — programs, receipts, drawings, listing — is in
[`showcase/squatchee_spin/`](showcase/squatchee_spin/), and
[`showcase/README.md`](showcase/README.md) walks the claims to the receipt behind each.

## Layout

| path | what it is |
|---|---|
| [`crates/kernel-core`](crates/kernel-core) | math, `Mesh` + mesh I/O, exact predicates, BVH, validation and repair, DFM and support reports |
| [`crates/kernel-implicit`](crates/kernel-implicit) | SDF primitives, TPMS lattices, CSG and blends, manifold dual contouring, mesh→SDF bridge |
| [`crates/kernel-brep`](crates/kernel-brep) | analytic surfaces, half-edge topology, persistent naming, booleans, fillets, NURBS, STEP import/export |
| [`crates/kernel-model`](crates/kernel-model) | feature tree, sketch solver, assemblies and mates, parts catalog, materials, drawings, campaign gates |
| [`crates/kernel-api`](crates/kernel-api) | the JSON op surface and the one `Report` type everything speaks |
| [`crates/agent-bench`](crates/agent-bench) | the agent-surface ruler and end-to-end benchmark |
| [`studio/`](studio/) | HTTP server, web IDE, terminal client (`lmcad-tui`), MCP server (`lmcad-mcp`) |
| [`tools/`](tools/) | the Python analysis layer: [`analyzers/`](tools/analyzers/), [`publish/`](tools/publish/), [`validation/`](tools/validation/) ground-truth pins, [`tests/`](tools/tests/). Old flat paths still work via shims |
| [`campaign/`](campaign/) | the contract an agent designs under: [operator brief](campaign/OPERATOR_BRIEF.md), [deliverable spec](campaign/DELIVERABLE_SPEC.md), [op digests](campaign/digests/), [publishing spec](campaign/PRINTABLES_LISTING_SPEC.md), [friction logs](campaign/friction/) |
| [`legacy/`](legacy/) | parked and **not built**: `kernel-gpu`, `kernel-wasm`, the pre-JSON example campaigns |

The 52 hardware-catalog ops no campaign uses sit behind a default-on `catalog` feature —
see [`docs/OP_USAGE.md`](docs/OP_USAGE.md) for the census (161 dispatched, 84 used).

## Honest limits

- **Voxel FEA under-reads peak stress** by roughly 20 % against a converged mesh — from
  the conservative side, and the receipts say so. Modal reads slightly stiff; buckling
  factors are upper bounds.
- **Half the analysis surface is below the validated line.** 9 of 18 analyzers are
  Validated (manifest plus ground-truth pin), 7 Demonstrated, 2 Cataloged. Run
  `python3 tools/analyzer_registry.py` for the ledger; tier is evidence, not a vibe.
- **Optimized parts come back as meshes.** There is no density→B-rep reconstruction.
- **The implicit↔exact bridge is one-directional by contract.** Fields leave as
  voxel-accurate meshes, never as exact B-reps.
- **Coincident-face booleans are a real frontier** and are refused rather than
  mis-stitched, with the refusal naming the remedy.
- **Fillets are convex rims only**; NURBS faces tessellate at a cut; STEP lacks
  trimmed-NURBS faces and sphere poles.
- **Vendor STEP is graded.** `mode: tolerant` repairs or skips bad faces and reports every
  solid with name, envelope and status. Framework's Expansion Card and battery import
  completely; their 45 MB, 168-solid mainboard is census-only and its full import is
  unverified.
- **Fatigue data is thin and says so.** Only PLA has measured printed S-N; across-layer
  fatigue is unknown for every material and the runner refuses rather than guess.

## Verify it yourself

```sh
cargo test --workspace --release                              # the full suite
cargo clippy --workspace --all-targets -- -D warnings         # zero warnings
cargo run --example parts_gallery -p kernel-model --release   # end-to-end acceptance
python3 tools/audit_docs.py                                   # docs vs source, gated in CI
python3 tools/analyzer_registry.py                            # the analysis ledger
```

Rebuilds are deterministic, so re-running a program reproduces the committed STL
byte for byte:

```sh
cmp showcase/squatchee_spin/print/squatchee_spin_prop.stl out/capspin/squatchee_spin_prop.stl
```
